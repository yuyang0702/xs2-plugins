# 人物中心与叙述偏好设计

用户已在本轮明确要求按上一条完整清单与顺序实施并测试；此文落实已批准的范围，不重复设置方案审批门槛。

## 目标与现状

先改善正文：全链路规则体检、按书采用的叙述偏好，不用固定对白配额。再把现有按人物声音编辑扩展为人物中心，最后补齐章节状态、成长、试读和真实进度。原有 voice_support、参考采用、story_support 已有事实/知识/正文依据和版本检查，必须复用。业务由 xs2-novel-flywheel 插件负责，主程序只作访问控制、模型/任务传输和 UI。

## 已决定的实现方式

采用现有插件能力渐进扩展，增加 prose_policy 和 character_center 脚本服务，并复用现有持久化小说助手任务与隔离模型传输。不另建人物数据库或生成引擎，不把业务规则复制到 React/FastAPI。独立系统会分裂事实来源；直接替换旧档会损害兼容性，均不采用。

## 全局约束

- 未显式采用时，GET、刷新、预览不能改写现有小说、配置、角色卡或声音；旧卡原文保留，无法唯一解析时只读显示并明确提示。
- 不修改模型配置、全局默认、API 密钥、代理或既有工作流用户模型偏好。不推送远端。
- 新持久化只在当前书 learning/ 下的本功能路径；手工局部编辑经预览与确认后只修改选中原文片段，保留其他人物、BOM、新行格式和事实。必须有历史、乐观版本检查及可审阅回退。
- 路径限制在工作区内，拒绝绝对/..、越界链接、无效章节/人物/来源，不创建缺失小说工作区。由宿主执行 owner/execution-policy、manual-control 和 busy 检查。
- 作者硬要求、世界事实、已发生状态、模型建议明确区分；不把正则线索当语义裁决，不按关键词自动软化事实。
- 将未来弧线/规划与正文已确认状态分开。状态回放须有正文哈希/依据；旧/失效/重置快照不能作为当前事实。
- 不按每段动作、沉默、对白数量、标点或句长配额来制造人味；关键要求、证词、报价、拒绝及自然回应保留。
- 不增加每章默认模型调用；人物图、状态、规则列表和统计优先使用已有数据。AI 改写/试读由用户发起，失败不得自动写正文或正式人物资料。
- 所有真实模型比较与测试用隔离目录，禁止修改现存样书。提交范围不含小说、配置、截图和测试临时文件。

## 一：叙述偏好与全链路规则体检

prose_policy 提供只读 audit(root, chapter)、read(root)、save(root, payload, expected_revision) 和运行时上下文/有效文件函数；具体契约写入 SCRIPT.md。

本书模式为 inherit / narrative_led，默认 inherit。narrative_led 让行动、感知、取舍承担更多叙事，保留关键对白、普通回应与人物声音，不靠工艺步骤、心理标签和景物凑字数。

体检覆盖人物档案/声音、故事规划、卷纲近纲、本章细纲/共同上下文，显示来源、原文、定位、原因、来源类别和建议。固定应对、每句必须推进、对白后重复解释等只能是待核对线索；普通剧情先后、知识限制和作者硬事件不能误判为机械规则。

旧文件不批量重写。用户可选择表达性规则，预览并确认替代表达，记录来源哈希与原文。生成时采用精确绑定的任务内有效副本，所有有关下游消费者读取同一偏好和有效规则，避免只在末尾追加提示而仍夹带旧硬命令。来源变更则提示重新核对，不静默应用过期覆盖。不可覆盖身份事实、世界规则或不可定位的原文。

新生成规划/细纲/正文/润色/评估的提示词协调：人物倾向不是固定动作或台词步骤；规划建议不是已发生事实；叙述与对白按场景取舍；普通回应可有个人味；不把每句的功能作为必须当场解释的义务。保留现有输出契约和正常节点调用数。

## 二：人物中心

角色视图包含概况、性格动机、关系、声线、本章状态、成长/计划、原文与修订记录。采用已有 Markdown/JSON，不能靠名称模糊匹配拼接身份。分节编辑优先选中有唯一来源的章节，不允许任意路径或泛用 JSON patch。未知旧格式继续展示原文和旧声音编辑入口。

关系视图提供有方向的关系对象、性质、意义、态度和张力；未知对象保留文字，不臆造新人物。概况和缺失字段不能推断补写。成长显示计划与实际变化，状态按章查看知情/误解、目标、处境、关系和原文证据。

局部修改：先展示前后差异、影响范围，再确认。存储原片段/新片段、来源版本与时间，回退也走当前版本下的片段预览，不整本回滚。AI 只为表达性字段提建议；事实/身份/经历字段不由模型自动改写。

AI 改写与场景试读复用现有小说助手持久化任务、限时与有限重试。输入绑定当前人物/关系/场景、已确认上下文、来源版本；结果必须校验版本与输出格式。试读提供对照文本、待核对点，可记录作者认可与理由，但不把样句变为必须复述的台词。角色/场景适配参考继续用已有写法学习结果。

## 三：前端与进度

现有 humanware 深链保持兼容，导航改为人物中心。独立人物选择、搜索、分组阅读、关系视图、局部编辑/预览/确认/历史、章节选择、事实与计划状态标识、写法偏好和规则体检、可选 AI 改写/试读与认可均需可操作。

进度基于真实任务节点和实际产物，区分规划/草稿/评估/确认/导出。展示当前节点、已完成节点、耗时、模型与实际 token/call 记录（有数据才显示）；费用未知不编造，不把阶段百分比当 token 或质量进度。失败重试与停下原因可见，短篇不强制逐人七维深化。

## 验证与激活

TDD 覆盖旧卡/重复姓名/代码块/多语言/缺失字段、BOM/CRLF、仅改选中片段、过期预览、正文哈希失效、越界路径、忙碌任务、插件禁用、重复请求、模型错误/空输出及不自动采用。

用旧坊挽留、阿杏作证、夜间制幡三段作真实模型前后比较，固定事实、结果、视角、篇幅和模型设置，检查对白/描写、信息保留和节奏。小样本不作质量普遍保证，不以对白占比判好。

完整插件回归、宿主相关测试、前端构建与 UI 操作均须通过。实际运行升级使用项目已有资源映射/三方升级工具，保留用户模型选择；只在服务空闲时按现有启动器重载。完成前核对原小说与配置哈希。
