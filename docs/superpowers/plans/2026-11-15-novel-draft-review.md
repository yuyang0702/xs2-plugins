# 小说初稿与审改流程实施计划

> **执行方式** 依次实施三个步骤，每步先验证回归用例，再推进下一步。

目标是在同一模型下减少短篇单写手的重复输入，让初稿只在发现具体问题后改动，并逐组核对表达补丁的实际作用。

## 1. 短篇单写手输入

- [x] 用真实模板展开与短篇准备脚本复现同一来源重复。验证长篇和多写手仍能获取各自资料。
- [x] `short_preparation.py` 按短篇单写手路径生成任务级简报。`mvp/definition.json` 由写手专用变量选择短篇简报或原有上下文，并保留角色适配、文风、确认计划和权限的来源。
- [x] 固定两本书的源文件、当前模型和字数范围，用隔离副本留存原工作流基线。

## 2. 先审后修

- [x] 通过真实工作流及脚本测试清洁稿直通、有据问题触发返修、返修后重新核验和旧任务恢复。
- [x] `draft_guard.py` 各阶段先核对冻结稿，再由工作流决定是否启动修订，并保留候选摘要和现有发布凭据校验。
- [x] `reader_review.py` 和盲审输出定义为关键决定分别绑定获知信息与作出反应的原文。仅在连续场景有时序依据时对照文本位置，兼容旧报告和刻意变换叙事顺序。

## 3. 对照补丁前后

- [x] 用有效补丁和有损补丁测试候选核验，另测试空补丁与旧任务。
- [x] 借用现有局部返修的改动复核语义，为表达补丁注入原稿、候选稿与分组证据，逐组验证实际净效果。
- [x] 运行插件测试及工作流检查，用《退潮以后》《关灯以前》的隔离副本跑完整前后对照并记录实际模型、初稿、成稿、节点路径和读感。
