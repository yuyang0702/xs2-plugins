# 学习写作与本书阅读目标

“参考资料蒸馏”现支持 `learning_direction`：默认 `general`，可选 `zhihu_short` 或 `custom`，后者结合 `learning_focus`。它们只改变分析的关注点，不声明参考资料来自某个平台，也不直接改变任何作品的风格。

页面操作：进入“资料蒸馏”，点击“刷新工作流”，再点“查看全部参数”；“学习侧重点”显示为“通用 / 知乎短篇 / 自定义”。未选择时仍默认通用。

部署检查须包含程序实际读取的 `data/workflows` 定义及运行中的工作流接口，不能仅验证插件 checkout。手工改过的工作流可能因 `user_modified` 冲突保留旧版；使用主程序已有的、带备份的三方升级方法审阅合并，保留模型偏好和本地检查，不覆盖任务快照。前端选项使用 `{name,value}` 对象，不能只提供字符串数组。

分析者可为有原文证据的机制提供 `reading_objectives`：抽象目标、规划问题、验收问题和适用边界。维度为开篇期待、信息显露、关系发展、兑现、声音或自定义。程序核验原文证据，目标不得直接抄入来源正文。无依据时不产生目标。旧库仍可使用；旧机制不会自动补出新的约束。

作者在本书明确选择后，目标跟随版本化蓝图进入 `reading_contract`。顾问能看到目标并建议选用；通过顾问采用时，兼容性复查还须逐项适配本书，不能漏掉目标或改换维度。顾问建议本身不等于采用。原作剧情、人物和分析引文不进入创作规则。

有目标时，现有内容与篇幅规划会启用，`goal_plans` 逐项说明对应分段、读者起点/终点和本书依据；独立复查用 `goal_checks` 检验。没有篇幅策略的书沿用作者当前范围，不因学习目标放宽篇幅。每章可以说明某项不适用，但须给当前章范围及本书依据。目标变更会使旧规划及进行中的审稿失效，不撤销历史事实档案。

作者明确的整篇范围与内部建议预算分别处理：规划顶层保留作者范围，分段预算的上下限合计可以更窄，但必须全部落在作者范围内。由规划者自行决定的配额仍要求分段合计与顶层配额一致。这样“最多五千字”不会变成必须用完五千字，也不会因为多场分配而被当作作者要求冲突。最终篇幅验收始终使用原有作者边界。

写手与局部修订读取同一组目标及已批准规划。表达核验、局部修订复查和整篇读者审查提供 `reading_checks`，每项必须有当前正文引文、理由和本书风格依据；缺项或假引文退回审稿，中高优先级返修不能被事实通过覆盖。事实、视角、因果、表达和篇幅的原有验收保持独立。初稿的事实阶段不承担阅读效果评估，后续表达阶段必须评估。

盲读仅提供公开的通用维度问题，不公开私有目标答案及计划；自定义目标可能暴露剧情意图，仅由资料复审逐项评估。资料复审保留全部目标，不因盲读未收到某项目标免检。未解决的盲读问题继续阻止通过。

知乎短篇方向可关注开篇承诺、信息释放、情绪/关系和结尾兑现，但不强制第一人称、反转、短句或段长。静景、议论、心理、慢热、开放结尾和不可靠叙述按本书规则判断；采用的是具体阅读作用，不是统一模板。

`evals/verify_reading_chain.py` 在独立副本上调用真实节点提示、结构与程序门禁，记录原始响应和 Token。测试原稿及已停止长跑的文件哈希受保护；脚本不启动小说驱动器。真实模型拒绝或返修结论保留，不能将回归通过当作文学质量通过。
