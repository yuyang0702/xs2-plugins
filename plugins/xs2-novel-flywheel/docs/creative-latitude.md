# 人物与参考资料的使用

人物卡用于理解性格、价值、关系与矛盾，不安排每场的应对流程。人物可以误判、撒谎、自欺或冲动；人物自己的信念不会因此变成世界事实。作者明确要求、已发生的事实、关系归属和知识状态继续受到保护。

参考写法与风格方法按场景选用。选中表示允许借鉴，不要求逐章体现；未使用不触发补写或返修。作者另行明确要求的表达效果仍有效。风格档案的 `commandments` 允许为空，只记录有依据的作者禁令或已确立边界，不从题材标签生成额外禁令。

## 插件实现

- `resources/script-library/xs2/prose_policy/creative_latitude.py` 保存共同解释及人物、规划、审核用途。
- `tools/wire_creative_latitude.py` 将指导写入插件提示词，并替换相冲突的旧条款；重复运行不改变结果，不改工作流图、模型参数或输出结构。
- 短篇上下文和本书契约使用相同解释。短篇单写手保留作者明确意图，避免依赖其他消息才能找回要求。
- 参考渲染将旧阅读问题标为“实际采用时评估”，保留原问题、目标编号和蓝图哈希。持久化蓝图与人物资料不做关键词迁移。

通过插件安装和资源命名空间机制发布这些变更；不要直接维护宿主的工作流副本。已有任务冻结的资料保留；启动新任务后使用更新资源。已经写成的正文不会自动改写。

## 验证边界

回归测试检查资料权限、参考建议不阻断审核、作者要求保留、蓝图不变、提示词生成幂等性及插件可移植性。这些确定性检查不能证明小说已经具有更自然的语感。文学效果仍应通过保留旧稿的同场景对照生成与阅读判断，不使用句长、禁词或“人味”分数代替阅读。
