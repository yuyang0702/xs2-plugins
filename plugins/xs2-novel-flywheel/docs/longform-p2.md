# 长篇 P2：跨卷、滚动规划与连续运行

连续创作会在写下一章之前检查本书卷级范围、实际归档与计划窗口。窗口不足或实际发展偏离假设时，进入既有 outline 工作流的独立滚动分支：冻结资料 → 候选规划 → 来源核验 → 独立验收 → 事务发布。原有手动卷纲/近纲流程和短篇流程保留。

## 配置本书

首次连续创作自动建立 `meta/serial_contract.json`：默认一个开放卷，规划未来 6 章，不把旧卷纲的预计结尾当作作者确定的终点。多卷范围、长线与退出条件由本书配置声明；当前没有专用的图形配置编辑器。示例：

```json
{
  "schema": 1,
  "planning": {"horizon": 6, "authority": "bounded", "max_input_chars": 120000},
  "volumes": [
    {"id": "v1", "title": "前卷", "start": 1, "end": 30},
    {"id": "v2", "title": "后卷", "start": 31, "end": null}
  ],
  "threads": [{"id": "old-promise", "intent": "本书作者声明的一条长期承诺"}],
  "run_limits": {"max_dispatches": 10000, "max_chapters": 9999, "max_stage_attempts": 8}
}
```

卷范围从第 1 章连续排列，只有最后一卷可开放。`horizon` 为 1–24，是有限规划覆盖范围，不是高潮、场景或描写配额。`max_input_chars` 限制本次规划输入，超限会暂停，不静默删掉关键资料。运行上限是技术预算，可按本书调整；可选 `max_elapsed_seconds` 表示本轮运行开始后的墙钟时间，包括暂停时间。

`bounded` 允许在既有书契约和已声明卷范围内采用通过独立审查的计划。`review` 只保存候选，等待作者采用；审查发现方向范围改变时也等待采用。没有声明下一卷范围、卷级条件未达成或作者计划失效时暂停。新卷不能靠程序擅自扩大范围。

长线可选，不要求每本书建立同样的线索。若作者需要卷级退出条件，可在某卷增加 `"exit_conditions":[{"thread_id":"old-promise","status":"intentionally_open"}]`；可选状态还有 `advanced`、`resolved`。没有退出条件时，不强迫结清伏笔、人物关系或债务。

## 跨卷承接与重新规划

承接读取前文可信快照中的实际人物、世界、索引与有证据的长线状态。卷纲是意图，不能冒充已发生事实。后验仲裁器只有引用当前真实正文，才能提交 `serial_progress`。状态可为推进、解决或有意悬置，`requires_replan: true` 表示实际发展需要调整未写计划。人物的作者身份映射依然不等于人物已知，非线性时间和叙述权限沿用 P1 与每书契约。

候选可为关键人物声明 `expected_state`（`entity_id`、`path`、`equals`）；开始写该章时，实际归档与假设不符会触发重规划。旧事实、每书规则、采用方向或来源有变化，也不会继续使用过时窗口。

滚动发布仅更新未写章节的计划，保留旧版本、审查、输入和发布凭据。近纲只替换程序自己拥有且未被作者改动的滚动段落；已写正文、作者采用的 JSON 计划和作者编辑的段落都会受保护。窗口遇到未来已写或已采用计划时提前结束。

在作品副本目录使用已安装脚本库运行方式执行以下命令（`TASK_ID` 必须是本次滚动任务的真实编号）：

```powershell
$env:TASK_ID = 'author-reviewed-window'
python story_support.py serial --serial-action status --chapter 0031
python story_support.py serial --serial-action approve --chapter 0031
```

上例中的 `story_support.py` 指脚本库 `xs2/story_support` 的主脚本，不是作品中的文件。`approve` 仅用于已经留存并由作者核对过的待采用候选；候选或审查之后有变化，旧预览不能用于采用。采用后回到工作台继续原流程。`prepare`、`normalize`、`commit` 由 outline 工作流调用。

## 中断与预算

派发前在 P0 SQLite 建立运行和派发凭据，复用主程序任务引擎。重复轮询和重启重用同一凭据，不重复计算派发；同一任务人工恢复的新增执行记录会持久计入恢复成本，快速再次失败也不能漏算。新任务派发检查总次数、章节数、同章同阶段尝试数及可选时间预算。

滚动输入和发布复用 P0 持久事务、来源/目标版本核对与恢复。发布成功而最后节点失败时，自动核验本次凭据后继续，无需重跑规划模型。来源或目标已变则停止恢复，保留诊断供复核。删除长篇配置不会自动清空历史运行预算；已存在运行的书需要恢复其配置。

预算到达上限会暂停，当前没有“一键清空账本重试”功能。显式完成的批次会关闭本轮运行；普通暂停不会重置预算。主程序之外直接手动执行的模型任务不受插件派发前预算控制，插件再次观察时会核对其恢复记录。不能据此承诺外部模型计费恰好一次。

## 验证边界

专项测试和 `evals/verify_longform_p2.py` 使用隔离副本、真实 CLI、主程序工作流路由及故障注入。五种风格副本的候选、审查和附加章节都是明确标记的离线测试资料；不调用远端模型，不重新生成小说。它验证流程与原稿保护，不能证明百万字实跑性能、远端模型稳定性或文学质量。
