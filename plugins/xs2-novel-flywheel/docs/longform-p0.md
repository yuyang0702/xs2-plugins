# 长篇 P0：可信归档与恢复

本次功能全部位于小说插件，不新增文风、题材或章节节奏限制，也不更换宿主任务引擎。

每本书的 `archive/longform.sqlite3` 保存不可变的提交输入、观察候选、仲裁结果、完整输出、来源哈希及追加式运行事件。正文和作者确认的每书规则仍是依据。存储文件应与整本书一起备份，不能单独删除来修复档案。

提交分为持久化 pending intent、原子文件替换、complete 凭据三个阶段。SQLite 事务负责跨进程串行化，磁盘文件和数据库之间通过提交日志恢复；不假设多文件替换具有天然原子性。读取时拒绝 pending、篡改或已失效的受管快照。重复提交同一输入复用原凭据；后续章节绑定前文正文及确认档案版本。旧书未纳入账本的快照保留原有来源检查，不冒称完成了新审核。

生产策略记录启动、任务派发状态、失败及核验完成事件，包括宿主 task_id、章节、输入/模型配置版本及产物哈希。post-hoc 完成还要求本任务的归档节点成功且凭据属于本任务。账本不提供外部模型请求只收费一次的保证。

`story_support recover` 会在正文、规则、依赖和目标版本一致时重放未完成提交。context、preflight、begin-review 和生产检查也会先尝试恢复。

发生源资料变化或目标冲突时保留现场，拒绝覆盖。操作者可先备份和检查，再显式运行 `story_support abandon-commit --chapter 0001`：只将该章 pending intent 标为 abandoned，保留诊断和已有文件；随后重新审核、归档。它不会自动修正文稿或重置已完成凭据。

独立视图提交也可用 `abandon-commit --commit-id <recover 输出中的编号>` 精确放弃。已完成档案不依赖可清理的 review cache；未完成提交恢复时仍核对冻结输入。

后验管线 v10 按 TASK_ID 与章节隔离 review-source、观察员及仲裁员产物；有任务编号时不回退读取共享缓存。归档节点中断但前置节点已完成时，自动流程核验本任务提交凭据后复用原后续决策，避免重跑模型，并保留“仅返修复评”的完成边界。

独立 refresh 也使用提交日志；它只能从有效快照重建派生视图。归档与旧章修订不自动改写后文。

P1 的实体编号、远距检索和精细影响传播、P2 跨卷规划不在本次交付范围。P0 的来源核验不能取代对模型语义判断的审稿。
