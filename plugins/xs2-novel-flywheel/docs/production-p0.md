# 运行预检、输入视图与修订收敛

这些能力由小说插件和插件工作流提供。模型、每书风格、世界规则、作者篇幅范围和独立验收继续使用原有设置。

## 数字按作用判断

写作、审稿和修订都会检查精确计数是否承担叙事作用。金额、期限、技术参数、资源账、人物计数习惯和有意夸张可以保留。程序不设置数字配额，也不把数字多直接判成问题。

“这几个字”等指代只有在引语紧邻、唯一、计数规则明确时才产生可复算的事实候选。其他情况保持未知，交给独立审稿结合上下文判断。建议提示不直接改稿或决定通过；修订仍须提供逐字补丁和当前稿依据。

金额别名只在有依据的同一账本内使用。人民币作用域和其他单位的等值关系须有本书资料支持；不同币种、资源品阶和未知兑换率不能自动合并。原始引文保留。

## 正文调用之前

工作流先核对变量、脚本、可用的模型参数信息和资源版本，保存不可覆盖的运行清单，再读取各角色的完整输入并记录预算。正文、每书规则和作者要求不会被静默截断。大型机器证据目录留在本地，程序继续用它们核对模型引文。

规划输入中的旧审稿或旧冲突如果明确绑定了另一个正文版本，会标为过期诊断，不作为当前事实。当前正文、有效审稿判断、作者要求和本书规则完整保留；当前有效冲突仍完整提供。

预算区分估算和服务商实报。宿主注入的完整工具定义、历史、服务端压缩、精确分词等无法在脚本边界完整观测时，记录为未知。显式容量不够时暂停并保存覆盖诊断，不缩短小说或删掉必要规则。

## 修订与恢复

新局部复查统一输出 `local-review-v2`，旧报告仍可读取。程序只展开可从本次真实补丁确定的绑定字段，不制造文学判断。目标编号或证据缺项须重新补审；可以定点补审时保留其他实际判断，最终仍验证完整报告。

移动等相关补丁使用同一 `group_id`。只有明确独立的等价改动才可撤回，撤回后重新组装、检查篇幅并要求新的独立复查。原子组不会只保留移动的一半。重复拒稿本身不证明必须重新规划；真正退步、未解决问题和作者范围冲突继续阻止发布。

自动启动意图先完成参数校验并冻结意见资料，再在现有归档数据库中登记。相同待启动意图复用相同参数和执行权。不能确认是否已经创建任务时保留记录，不根据等待时间抢占。直接使用宿主 API 创建多个任务的入口无法由插件改写；插件在付费步骤和提交边界限制有效执行。

章节提交核对作品执行所有者和代次。归档意图、恢复重放和正文替换与执行权检查共享数据库写锁；已失效的旧执行不能发布。版本更新应在阶段检查点进行，历史任务、模型设置和原稿不因升级清除。

## 查验记录

每部作品的 `cache/production-runs/<task>/manifest.json` 保存运行版本和绑定；`budgets/` 保存角色输入预算。原生任务保留尝试、模型调用和实报 Token。现有 `archive/longform.sqlite3` 中增加执行意图和分类重试记录，继续复用原归档账本。

相同确定性格式或证据错误重复出现时停止盲目付费复审。不同的内容修订继续使用有界预算，保留有效工作稿；暂停时不会把尚未通过的候选当作完成稿。

有原生任务、冻结运行清单和自动恢复凭据支持的续跑共享同一逻辑重试额度。已观测到的失败尝试按任务、节点和尝试编号对账一次，重复轮询不会再扣，成功的必要审稿不会扣。新的手动任务、另一章节或有实质变化的作者要求、正文、模型、代码使用新的意图。宿主未暴露的 SDK 内部 HTTP 重试次数仍记为未知，不能把插件额度当作精确的 HTTP 请求上限。

连续两次候选篇幅不合格本身不证明阅读要求无法满足。程序继续阻止未达字数的候选发布，并有界返修或暂停；重新规划须另有当前原文与作者要求支持的真实冲突依据。
