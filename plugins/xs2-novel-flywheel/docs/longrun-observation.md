# 在副本中验收真实长篇生成

`xs2/longrun` 是可选插件脚本库，把长跑绑定到独立副本、授权模型、预算和新增实字目标，复用 P0–P2 写作、修订、读者评估、后验与导出。检查遵循每书风格、叙述权限和世界规则，不规定高潮频率、描写比例或长线收束方式。

## 建立与运行副本

用库函数 `ledger.initialize_copy(source, destination, config)` 建立新副本与来源哈希清单。目标不能已存在或与来源嵌套；来源中的符号链接会被拒绝。原有章节记作基线，不计入新增实字。

`meta/longrun_contract.json` 与 SQLite 冻结配置须一致，包含 `schema: 1`、`target_new_characters`、授权 `models`、模型到服务地址的 `routes`、`limits`、`pricing` 和 `external_run_authorized: true`。本次外发服务与预算需作者明确授权。当前通过配置和脚本使用，没有新增专用图形界面。

在副本目录，用主程序 Python 执行已安装插件的 `runtime/longrun/main.py`：`run --host-root C:/xs2/DeterminFlow --resources <该安装版本的resources绝对目录>`。脚本库 `xs2/longrun/longrun.py status` 独立输出汇总，`prepare-audit --chapter 0002` 准备证据包。`run` 是持续命令，应在可保存输出的终端执行。

主程序配置只读，原生会话、日志和运行数据隔离在副本 `observability/runtime-data`。脚本库保持独立，插件自己的运行模块适配原生 SessionManager、WorkflowEngine、AgentNode、ScriptNode、工具装配和运行身份核验，不模拟模型回复。未连接外部 MCP 服务。

## 观测与验收

`observability/longrun.sqlite3` 保留调用预留与结果、任务状态、章节版本、审查和恢复事件；`observability/report.json` 提供机器可读汇总。实字沿用插件口径：汉字按字、英文和数字按词，标题、标点和空白不计。

只有当前可信归档、当前通过的读者报告及已完成导出任务绑定的新增章节才计数。正文或凭据变化后，该版本从当前累计中移出，历史费用与记录保留。达到字数、语义覆盖和问题状态分别呈现，达到字数不等于文学质量通过。

每章后验后独立抽样第一章、近期章节、轮换旧章、对应快照和本书规则，检查 memory、cognition、volume。问题和适用检查须引用输入中的连续原文。结论、检查状态和问题清单矛盾时拒绝接受。没有复述旧事不等于遗忘，旧档案仍可回取的信息不因最新快照没重复就算遗漏。

审查者可提交带来源的自然提问作为后续检索探针。未命中只表示该查询没有召回指定片段，不自动等同模型遗忘或正文矛盾。抽样审查不证明全书没有隐含问题，报告保留范围和证据。

人工核对发现的问题以 `manual_observation` 事件单独保存，保留来源哈希、证据和来源说明，汇总为 `manual_observations.open`。后续模型通过不会覆盖这些未解决记录；来源改变只标记证据需重查，不自动当作解决。明确核对解决后，可追加相同问题 `id`、`status: resolved` 的人工事件。存在未解决人工记录时，达到字数仍为 `needs_review`。

## 中断与费用

控制器采用持久意图、目标前后版本核对与原子文件替换，同时恢复作品状态、章节/阶段游标和相关任务快照。控制器允许明确的本章意图变更，以冻结长跑配置为依据；事实档案仍由 P0 管理。外部编辑造成版本不符时停止，不覆盖作者改动。

已完成节点保留，运行中断节点使用主程序原有历史与恢复入口明确重发，每任务最多两次进程中断恢复，费用累计。不承诺未收尾会话的最终回复总能复用。操作性错误另受 P2 和既有有限恢复策略约束，内容门禁不被忽略。可记录一次已提交章节边界的安全进程重启验证。

维护停止可写入 `observability/stop-request.json`，包含唯一 `id`、`after_stage`、`reason`，可选四位 `chapter`。运行器只在该阶段完成、作品状态和下一阶段游标已持久化后停止；同一请求不会重复生效。恢复后从已保存的下一阶段继续。更新插件时，尚未完成的原生任务仍须使用其冻结资源版本，不将旧任务快照改写成新版本。

若尚未发布本章正文，但事实稿已经过原任务核验、表达环节失败，可由插件 `recovery_checkpoint.prepare_review` 创建 `draft_review` 检查点。它复验旧任务、事实稿与审核凭据、计划及当前每书契约，将正文复制到不可覆盖的恢复种子；新原生任务重跑全部事实、表达、转换、渲染和发布门禁，禁用写手及写前规划。来源变化、已有作者正文或选择集改变时拒绝恢复。渲染后若仅尾部操作失败，则验证新稿凭据后转入既有发布恢复，不从旧初稿覆盖正文。检查点复用不是审核通过凭据，也不提前计入新增字数。

每次实际模型调用先持久预留，完成后保存服务返回的原始用量与规范化 Token，并以原生 run_id 与会话账本核对去重。错误或用量不完整时保留未知状态及预留，不把字符估算当实际用量。

独立审查与返修规划的辅助请求沿用主程序流式接收，再聚合为完整结果；用量仍由原生回调结算，连接中断不伪造完整回复。

沿用主程序版本化计价。缺适用单价时标为未计价、金额为 `null`；按配置计算的金额不是服务商实际扣费。未知调用不能显示免费。有上限时在调用前保守检查；绕开驱动的人工请求不受它拦截，生产流程观察到的历史调用仍会记录。

暂停保留现场和预算。最终报告必须按真实完成量记录，不把离线夹具计为真实生成，也不能因达到目标字数忽略未解决问题。

基线章节也必须经过当前每书规则下的读者复评。需要返修时，继续使用生产流程的范围检查、局部修订和有限返修次数；超出作者范围仍暂停，不把基线直接放行。作者允许修改验证副本时，可在副本的本章意图中明确最小修订范围后重新复评。基线修订始终不计入新增字数，来源原稿仍受独立哈希清单保护。

自动返修规划复用表达验收规则。不能用更多操作、同义解释或重复确认填补删减字数，也不能自行收窄作者的篇幅范围或规定情绪回响次数。方案明确标为自动建议，保留此前选中的意见原文、路径与哈希，作者原有要求优先；多轮自动方案仅继承原意见来源，不累积嵌套旧计划。应用前复验意见选择及来源，发生变化即拒绝旧方案。`automatic-origin.json` 保存来源与采用记录，方案本身不能被当作用户逐项确认。

MVP 和润色工作流提供每书的“章节篇幅归属”选择。“沿用本书”保留既有策略；“作者硬性范围”保持明确范围；“按内容规划”允许对程序分配的单章预算协商，不改变全书实际字数目标。配置保存在 `meta/length_policy.json`，可声明额外作者上下界。情绪、关系、氛围、语言形式和情节都可以承载篇幅，不强制每场新增事件或规定情绪次数。

启用后，原生流程先读取本书契约，再由独立的规划者与复查者校验各段阅读作用和预算合计，P0发布到 `planning/length/NNNN.json`。写作、局部修订和读者验收使用同一份已批准预算。原作者要求与旧自动建议分开；作者更新目标、选择或原意见时，旧预算失效。预算作为意图不会因正常正文修订失效，也不会被写入事实档案。

写手可以提交带冻结原文证据的 `needs_replan` 响应。连续两版内容修订与篇幅冲突，或连续两次有依据的实质修订仍失败时，也会返回规划；该路径不发布候选、不计入验收字数，并核对实际原生模型回复、源稿与复查凭据。旧书默认不新增规划模型调用；遇到已验证冲突时以作者硬范围启动有界规划，确实无法兼顾时停止并说明范围冲突。每章重规划最多两次，仍受原有连续运行派发上限约束。

重规划后的修订保留一轮同源、同每书契约的未验收候选及剩余表达诊断，避免换了预算便忘掉已指出的问题。候选哈希和旧报告须对应，旧凭据编号按该候选解析；仍逐字存在于当前原稿的问题进入明确目标，中高严重度的本轮自审问题也须逐项复核。旧候选是待复核材料，不是作者新要求、事实档案或通过凭据；作者改正文或规则后不再传入该旧候选。到达自动重规划上限时仍保存最新核验过的诊断，但不因此获得额外重试。
