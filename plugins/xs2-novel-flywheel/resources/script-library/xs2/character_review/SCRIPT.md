# New-card semantic review gate

Standalone standard-library CLI; run with the book as cwd and the workflow's safe `TASK_ID` environment variable. Existing canonical character documents or caches cannot be adopted or overwritten.

1. `preflight --premise TEXT --human-intent TEXT --world-intent TEXT --world-file PATH` claims the task and emits draft/review path `WF_VAR`s. `--world-file-stdin` instead receives the exact raw world path through the host's selected-variable stdin transport.
2. `render-compact --batch-dir PATH` invokes the existing compact renderer in draft cwd.
3. `prepare --batch-dir PATH` freezes author/world sources, all raw draft JSON/Markdown and renderer hashes, then emits `card_review_binding_sha` and the review input/result paths.
4. `apply --batch-dir PATH --binding-sha SHA` reads the actual selected review JSON from stdin, compares it with the saved review result, validates the schema, identity, voice shape and exact authority evidence, renders a separate candidate and exclusively publishes allowlisted first outputs.

Python interfaces: `preflight(book_dir, premise, human_intent, world_intent, world_file, task_id=None)`, `render_compact(batch_dir)`, `prepare(batch_dir)` return workflow-variable dictionaries. `apply(batch_dir, binding_sha, selected_output)` returns the publication receipt. `render_full(draft_dir)` invokes the existing full renderer CLI for synthetic integration and draft use.

New preparations use `xs2.character.semantic-review-input.v2` and require `xs2.character.semantic-review.v2` output; v1 cannot apply to these preparations. `card_schema` remains `xs2.character.v2`. The input has `task_id`, `source_sha256`, `mode`, `sources`, `characters`, and `frozen`. Authority IDs are `author.premise`, `author.human_intent`, `author.world_intent`, `world`, `locked.NAME`, and optional `locked.beliefs`. Each person has original `semantic_records`, `locked_records`, their exact `voice` object, and `editable_persona` entries `{record_path, field_path, original}`. Editable values are null in locked records while structure, targets, history, knowledge and unknown fields remain protected. Their originals appear separately in `draft-persona.NAME`, which is not fact or plot authority.

Each reviewed person returns the semantic fields, full voice, `changes`, and `persona_edits` (empty allowed). A persona edit is `{record_path, field_path, before, after, reason, source_id, evidence_quote}`: the exact allowlisted owned leaf, matching frozen original, nonempty plain string replacement, and exact source evidence. Each leaf may occur once. Only root want/fear/contradiction and indexed relationship dynamic strings are editable; full explicit-v2 records also expose relationship meaning/tension/attitude, world stance and possible challenge; full explicit-v2 deep records additionally expose the desire/fear/reaction/direction leaves listed in the input. This is not a generic JSON patch. Draft-persona may support preserving the same person's motives in personality, voice or persona edits, never facts/plot constraints. The reviewer returns one semantic set per person; every explicit v2 skeleton/deep record receives that same set. Unversioned deep fields remain immutable. Persona edits apply only to candidate JSON before the existing renderers; raw draft bytes remain frozen.

`source_sha256` binds canonical UTF-8 JSON with only its self-referential SHA field omitted; the exact complete input bytes have a separate frozen hash. Each changed field requires a real exact quote from an eligible source. Quote matching establishes provenance; the model's semantic quality must still be checked in live acceptance.

The journal `publication.json` contains task/source/review/output hashes. Individual complete staged files are published with exclusive hard-link creation, never replacement. A partial publication can resume only while each existing destination remains the owned staged file with the expected hash. Changed user bytes and completed destinations deleted by the user cause rejection. No cross-file atomicity is claimed. Raw drafts and candidate documents are retained for inspection.

`apply --retry-review` is an explicit workflow opt-in: only `ReviewCorrectionNeeded` (missing `changes` evidence for exact changed fields after all other review checks pass) emits the existing `WF_REJECT_UPSTREAM` tag targeting `agent_card_semantic_review`. The diagnostic includes only person names and missing field names, with audit code `character_review_missing_evidence`. Direct Python `apply` still raises and writes no candidate/publication. Blocked/source/binding/result/path/renderer/publication errors never become correction requests; existing output artifacts also prohibit correction. The host owns feedback injection, audit and the analysis node's existing two-retry budget. Input shape and source binding are unchanged by this correction mechanism.

The same opt-in also handles exact-quote mismatches for otherwise eligible evidence sources. `_evidence` raises `EvidenceQuoteMismatch`; only `_review` aggregates it with missing coverage after all strict checks. `ReviewCorrectionNeeded.quote_mismatches` lists person plus semantic field or persona record/path and source key, never the quote or replacement text; audit code `character_review_quote_mismatch` distinguishes it. Feedback requires copying a continuous exact substring without reordered words/punctuation. Unknown or unauthorized source keys, malformed evidence and protected edits remain hard failures; no fuzzy matching or source repair is performed.
